--------------------------------------------------
1. clangd: invalid --function-arg-placeholders + offsetEncoding deprecation warning (293 entries)
--------------------------------------------------
File: ~/.config/nvim/lua/opts/lspc/clangd.lua

Fix a — clangd 21 requires this argument to be an explicit boolean:
  - "--function-arg-placeholders",
  + "--function-arg-placeholders=true",

Fix b — "offsetEncoding capability is a deprecated clangd extension" warning
triggered by the offsetEncoding key in client capabilities. Testing showed any
value (empty table / null / false / string) still triggers the warning; only
removing the entire key resolves it.
The key is injected by nvim-lspconfig's lsp/clangd.lua default config
(lazy/nvim-lspconfig/lsp/clangd.lua: capabilities.offsetEncoding = { 'utf-8', 'utf-16' }),
and vim.lsp.config merges via tbl_deep_extend('force'), so nil cannot override
and delete it. Removed in the before_init hook instead:
  capabilities = capabilities,
  before_init = function(params, _)
    params.capabilities.offsetEncoding = nil
  end,

Verified: headless nvim opened a .c file, clangd attached with (offset_encoding=utf-8), zero new errors in lsp.log.

3. jdtls: "Exception: Unknown platform Android detected" (6 entries)
--------------------------------------------------
File: ~/.java-lsp/bin/jdtls.py  (get_shared_config_path)

Root cause: under Termux, platform.system() returns "Android", while the original
script only recognized Linux/FreeBSD/Darwin/Windows and threw an exception directly.

Fix — added an Android branch, selecting the shared config directory by machine
(config_linux references the x86_64 launcher, config_linux_arm references the
aarch64 launcher; this device is aarch64):
  elif system == 'Android':
      # Termux: platform.system() reports "Android"; reuse Linux configs
      if platform.machine() in ('aarch64', 'arm64'):
          config_dir = 'config_linux_arm'
      else:
          config_dir = 'config_linux'

Additional fix — same shebang issue ("#!/usr/bin/env python3"):
  termux-fix-shebang ~/.java-lsp/bin/jdtls

Also updated the outdated comment in lua/opts/lspc/java.lua ("Status: not enabled" -> enabled).

Verified: headless nvim opened a .java file, jdtls attached normally.
Residual noise: 3 JVM stderr lines at startup (incubator module warnings + Aries SPI-Fly INFO),
recorded as ERROR level by nvim but harmless and do not affect functionality.
