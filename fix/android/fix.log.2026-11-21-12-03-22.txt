LSP 修复记录 — 2026-11-21
=========================

来源: 检查 ~/.local/state/nvim/lsp.log (2293 行, 1908 条 error/warn)
三类问题: clangd 参数与弃用告警、bashls 不可执行、jdtls 平台不识别。
全部修复并以 headless nvim 实测通过。

--------------------------------------------------
1. clangd: --function-arg-placeholders 非法 + offsetEncoding 弃用告警 (293 条)
--------------------------------------------------
文件: ~/.config/nvim/lua/opts/lspc/clangd.lua

修复 a — clangd 21 要求该参数显式给布尔值:
  - "--function-arg-placeholders",
  + "--function-arg-placeholders=true",

修复 b — "offsetEncoding capability is a deprecated clangd extension" 告警
由客户端 capabilities 中的 offsetEncoding 键触发。实测任何取值
(空表/null/false/字符串) 都会告警,只有整键移除才干净。
该键由 nvim-lspconfig 的 lsp/clangd.lua 默认配置注入
(lazy/nvim-lspconfig/lsp/clangd.lua: capabilities.offsetEncoding = { 'utf-8', 'utf-16' }),
vim.lsp.config 按 tbl_deep_extend('force') 合并,无法用 nil 覆盖删除,
故在 before_init 钩子中删除:
  capabilities = capabilities,
  before_init = function(params, _)
    params.capabilities.offsetEncoding = nil
  end,

验证: headless nvim 打开 .c 文件, clangd 附带 (offset_encoding=utf-8), lsp.log 0 新增错误。

--------------------------------------------------
2. bashls: "bash-language-server is not executable" (22 条)
--------------------------------------------------
根因一: 服务器未安装。
  修复: npm install -g bash-language-server  (已装 5.8.1)
  安装位置: $PREFIX/lib/node_modules/bash-language-server (bin 链接到 $PREFIX/bin)

根因二 (安装后暴露): Termux 下 shebang "#!/usr/bin/env node" 找不到 /usr/bin/env。
  修复: termux-fix-shebang $PREFIX/lib/node_modules/bash-language-server/out/cli.js
  改写为 "#!/data/data/com.termux/files/usr/bin/env node"
  注意: npm 升级该包后需重跑此命令。

同时更新 lua/opts/lspc/bash.lua 过时注释 ("Status: not enabled" → 已启用)。

验证: headless nvim 打开 .sh 文件, bashls 正常附带。

--------------------------------------------------
3. jdtls: "Exception: Unknown platform Android detected" (6 条)
--------------------------------------------------
文件: ~/.java-lsp/bin/jdtls.py  (get_shared_config_path)

根因: Termux 中 platform.system() 返回 "Android", 原脚本只认
Linux/FreeBSD/Darwin/Windows, 直接抛异常。

修复 — 增加 Android 分支, 并按 machine 选择共享配置目录
(config_linux 引用 x86_64 launcher, config_linux_arm 引用 aarch64 launcher;
本机为 aarch64):
  elif system == 'Android':
      # Termux: platform.system() reports "Android"; reuse Linux configs
      if platform.machine() in ('aarch64', 'arm64'):
          config_dir = 'config_linux_arm'
      else:
          config_dir = 'config_linux'

附带修复 — 同样的 shebang 问题 ("#!/usr/bin/env python3"):
  termux-fix-shebang ~/.java-lsp/bin/jdtls

同时更新 lua/opts/lspc/java.lua 过时注释 ("Status: not enabled" → 已启用)。

验证: headless nvim 打开 .java 文件, jdtls 正常附带。
残留噪音: 启动时 3 条 JVM stderr (incubator modules 警告 + Aries SPI-Fly INFO),
被 nvim 记为 ERROR 级但无害, 不影响功能。

--------------------------------------------------
结论
--------------------------------------------------
lsp.log 三类错误清零。测试用临时文件已清理。
维护提示: npm 升级 bash-language-server 后需重跑 termux-fix-shebang。
